# 문서 실험: 에이전트가 직접 읽기 어려운 자료에서 가설 확인

[사전 실험](../pre/README.md)의 결론은 "문서화가 잘된 소스코드에서는 에이전트의 직접 탐색으로 충분해 지식의 효과를 잴 수 없었다"였다. 이 실험은 같은 가설을 회의록, PDF, HWPX, XLSX 묶음에서 확인한다. 이 형식들은 에이전트가 바로 읽기 어렵고, 개정본과 상충이 섞여 있어 직접 탐색이 약할 것으로 예상한다. 예상이 틀리면 그것도 결과다.

이 폴더의 스크립트는 일회용 실험 도구이며 제품 코드가 아니다. 절차의 뼈대와 스킬, 근거 검사·집계 스크립트는 사전 실험의 것을 그대로 쓴다. 여기에는 다른 점만 적는다.

## 1. 지켜야 할 것

- 원본 문서와 그 내용을 이 저장소(gotgan)에 올리지 않는다. 실험 폴더(`lab/`)는 어디에도 푸시하지 않는다.
- 외부 LLM으로 보내도 되는 자료만 쓴다. 가려야 할 내용은 **변환 전에** 원본에서 지운다. 변환 뒤에 고치면 근거의 위치와 인용문 검사가 깨진다.
- 원본 파일은 고치지 않는다. 매크로와 외부 링크를 실행하지 않는다.
- 사람의 승인 없이 지식을 정본(`lab/`의 `main`)에 넣지 않는다.

## 2. 자료 요건

프로젝트 소유자가 준비한다. 문서 20~40건을 권한다.

- 형식: 회의록(텍스트), PDF, HWPX, XLSX를 각각 포함한다.
- 같은 주제의 개정본이 있다(예: 계획서 v1과 v2, 날짜가 다른 회의의 번복된 결정).
- 서로 상충하는 내용이 있는 문서 쌍이 있다.
- 여러 문서를 종합해야 답할 수 있는 주제가 있다.
- 수치가 담긴 표나 시트가 있다.

실제 자료로 개정본이나 상충 쌍을 채우지 못하면 그 부분만 합성 자료로 보완하고 합성임을 기록한다.

## 3. 실험 폴더 구조

```
lab/                 # Git 저장소
├─ originals/        # 원본. .gitignore에 넣어 커밋하지 않는다
├─ text/             # convert.py의 출력. 커밋한다. 근거가 가리키는 대상
├─ knowledge/  flags/  tasks/  runs/  scores/  report/
```

## 4. 변환

```
pip install pdfplumber openpyxl pyyaml
python scripts/convert.py lab/originals lab/text
```

출력의 모든 줄은 원본의 위치를 대괄호로 달고 있다.

| 형식 | 위치 표시 | 예 |
| - | - | - |
| PDF | 쪽, 표, 행 | `[p3]`, `[p3 t1 r2]` |
| XLSX | 시트와 셀 범위. 수식은 값 뒤에 중괄호로 | `[매출!A3:D3] 2분기 \| 150 \| 95 \| 245 {=B3+C3}` |
| HWPX | 구역, 문단, 표, 행, 열 | `[s0 p12]`, `[s0 p12 t1 r2 c3]` |
| TXT, MD | 줄 번호 | 그대로 복사 |

`text/manifest.json`에 파일마다 해시와 상태(성공, 부분 추출, 실패)와 사유가 남는다. **실패와 부분 추출을 먼저 확인한다.** 처리하지 못한 파일을 숨기지 않는 것이 이 단계의 통과 조건이다.

알려진 한계:

- HWP(구 형식), 스캔 PDF, 그림 속 글자는 추출하지 못한다. 실패나 부분 추출로 보고한다.
- HWPX는 쪽 번호를 알 수 없다(쪽 나눔이 파일에 저장되지 않는다). 위치는 문단 순번이다.
- XLSX의 병합 셀은 왼쪽 위 칸에만 값이 있다. 계산된 값이 저장되지 않은 수식은 수식만 나온다.
- PDF의 표는 본문 줄과 표 행으로 두 번 나올 수 있다.
- 공개된 HWPX 시험 파일 49개로 확인했을 때 본문 글자의 99.7%를 추출했다. 한국어 실무 문서에서의 정확도는 확인하지 않았다.

## 5. 조건

| 조건 | 에이전트가 쓸 수 있는 것 |
| - | - |
| A | `originals/`만. 셸과 스크립트로 직접 연다 |
| B | `text/`만. 검색 도구로 찾는다 |
| C | `text/` + `knowledge/` |

회차 이름은 `a0`, `b0`, `c1`이다. 과제마다 맥락 없는 새 에이전트가 수행하고, 파일을 쓸 수 없는 읽기 전용으로 돌린다.

## 6. 과제

12개. `dev` 6개와 `holdout` 6개로 나누고 주제가 겹치지 않게 한다.

| 유형 | 수 | 묻는 것 |
| - | - | - |
| 단순 조회 | 2 | 한 문서의 한 곳에 답이 있다. 비교 기준이다 |
| 현재 유효한 내용 | 3 | 개정본이 있을 때 지금 유효한 것 |
| 상충 발견 | 2 | 문서끼리 어긋나는 내용을 찾아 둘 다 제시 |
| 여러 문서 종합 | 3 | 세 건 이상을 모아야 답할 수 있다 |
| 표와 수치 | 2 | 셀이나 표의 값, 그 계산 근거 |

과제마다 **정답과 정답의 근거 위치**를 채점 기준에 적는다. 정답은 소유자가 확인한 뒤 동결한다. 에이전트의 답에는 근거 위치(파일과 위치 표시)를 붙이게 한다.

## 7. 재는 것

사전 실험과 달리 비용을 처음부터 지표로 둔다.

| 지표 | 계산 |
| - | - |
| 정답 | 채점 항목 중 통과한 수. `dev`와 `holdout`을 따로 센다 |
| 근거 정확 | 답에 붙인 위치가 실제로 그 내용을 담고 있는 비율 |
| 근거 없는 주장 | 근거를 붙이지 않았거나 붙인 위치에 그 내용이 없는 주장의 수 |
| 비용 | 과제별 토큰, 도구 호출 수, 소요 시간 |
| 지식의 오류율 | 대조 검증에서 불일치로 나온 지식의 비율 |
| 사람의 검토 시간 | 승인에 쓴 시간(분) |

채점자는 "답이 맞는가"와 "근거가 맞는가"를 따로 판정하고 이유를 남긴다.

## 8. 절차

1. 준비와 변환. `manifest.json`의 실패와 부분 추출을 소유자와 확인한다.
2. 과제와 정답 작성, 소유자 확인, 동결.
3. `a0`과 `b0` 실행과 채점.
4. **천장 확인.** `b0`에서 `holdout`의 오답이 채점 항목의 3분의 1에 못 미치면 여기서 멈춘다. 변환된 텍스트와 검색만으로 충분하다는 뜻이다. 과제를 고쳐 오답을 늘리지 않는다.
5. 큐레이션. 입력은 `b0`의 `dev` 신고와 `text/` 전체다. 큐레이터는 신고받은 것만이 아니라 문서 사이의 개정 관계, 상충, 주제별 종합을 스스로 찾아 지식으로 만든다. `holdout`의 과제, 정답, 출력, 신고는 보여 주지 않는다.
6. 인용문 자동 검사. 근거는 `text/`의 커밋, 경로, 줄 범위, 인용문으로 적고 원본의 위치 표시도 함께 적는다.
7. **대조 검증.** 큐레이터와 다른 새 에이전트가 지식이 원문과 같은 말을 하는지 확인한다. 불일치는 고치거나 뺀다. 사전 실험에서 이 단계 없이 승인된 지식 9건 중 5건이 틀렸으므로 생략하지 않는다.
8. 사람 승인. 여기서 멈춘다.
9. `c1` 실행과 채점, 집계.

## 9. 판정 기준

실험 전에 정한다. 비교 대상은 B와 C이고, 근거는 `holdout`이다.

- **가설 지지**: `holdout`에서 C의 정답 수가 B보다 많고, 근거 없는 주장이 늘지 않았다.
- **비용만 개선**: 정답 수는 같고 C의 비용(토큰 또는 도구 호출)이 B보다 20% 넘게 줄었다. 원래 기획의 기준대로, 이 경우 큐레이션 범위를 줄이는 쪽으로 검토한다.
- **가설 약함**: `dev`만 나아졌다.
- **기각**: 나아진 것이 없다.

A와 B의 비교는 가설과 별개로 "변환과 인덱스만으로 얼마나 나아지는가"를 본다.

## 10. 한계

- 과제 12개, 회차당 한 번 실행이다. 방향을 보는 용도다.
- 채점을 에이전트가 한다. 소유자가 일부를 직접 확인한다.
- 외부 LLM의 결과다. 폐쇄망에서 쓸 내부 모델에는 그대로 적용되지 않는다.
- 합성 자료를 섞으면, 그 부분은 실제 문서의 어려움을 반영하지 못할 수 있다.
