# 개발 계획

초기 기획안 검토 결과를 반영한 계획이다. 기술 선정과 도메인 경계는 ADR로 확정하기 전까지 제안 상태다.

이 문서는 방향과 단계 순서만 담는다. 세부 계획 문서의 목록과 검토·승인 방법은 [계획 수립과 검토 절차](planning-process.md)를 따른다.

## 1. 계획의 전제

"원본을 검증된 지식으로 큐레이션하면 정확도와 재사용성이 오른다"는 것은 아직 가설이다. 그래서 순서를 **가설 검증 → 최소 큐레이션 루프 → 확장**으로 잡는다. 가설이 기각되면 큐레이션 파이프라인을 축소하고 "원본 + 인덱스 + 근거 뷰어" 제품으로 전환한다.

### 비교 실험

동일 문서, 질문, LLM 조건에서 세 가지를 비교한다.

| 조건 | 내용 |
| - | - |
| A | 원본 폴더 직접 탐색 |
| B | 원본 + 검색 인덱스 |
| C | 검증된 지식 + 원본 탐색 |

평가 항목: 근거 정확도, 근거 없는 주장 비율, 현재 유효한 정책 식별, 상충 문서 발견, 여러 문서 종합, 처리 시간, 토큰·자원 소비, 유지 비용. 유지 비용을 재려면 실험 중간에 원본을 개정하는 시나리오가 평가셋에 포함되어야 한다. 합격 기준 수치는 0단계에서 확정한다.

## 2. 설계 방향

- **정본 모델**: Git 커밋을 유일한 트랜잭션 로그로 쓴다. DB·인덱스·이벤트는 커밋에서 파생한다. ([ADR-001](adr/0001-canonical-store-and-consistency.md))
- **신뢰 등급**: 지식마다 `draft → self-approved → peer-reviewed → official` 등급을 가진다. 개인 Vault는 자기 승인을 허용하되 등급으로 드러내고, 팀으로 승격할 때 재검증한다.
- **수요 기반 큐레이션**: 반복되는 질문이나 원본 탐색 비용이 컸던 주제만 승격 후보로 올린다. 검색·질의 로그가 기준이다.
- **지식 단위**: Markdown 페이지 안에 주장 블록을 두고 블록마다 근거 ID를 붙인다. 유형은 사실, 결정, 정책, 절차, 장애 사례로 시작한다.
- **근거 앵커**: 위치(페이지·문단·셀·타임코드), 인용 텍스트, 해시, 파서 버전을 함께 저장한다.
- **3층 검증**: (1) 인용문이 원본 위치에 실재하는지 결정적 검사 (2) 다른 프롬프트·모델의 함의 검사 (3) 사람 표본 검수.
- **Stale 전파**: 근거의 역방향 인덱스로 원본 개정 시 의존 지식을 "재검증 필요"로 표시한다.
- **에이전트 런타임**: 자체 엔진을 만들지 않는다. CLI와 MCP 서버를 제공하고 기존 에이전트를 런타임으로 쓴다.
- **첫 화면**: 지식과 원본을 나란히 열고 인용 위치를 강조하는 근거 뷰어. Canvas는 이후 단계다.

## 3. 단계별 계획

### 0단계: 결정과 평가 기준

- ADR-001 정본·일관성 모델
- ADR-002 배포 등급(개인·팀·기업)별 정책 프로파일
- ADR-003 지식 단위와 근거 앵커
- ADR-004 권한 전파 규칙
- 대표 자료 선정: 회의록, PDF, HWPX, XLSX
- 평가 질문셋과 정답 근거 작성, 합격 기준 확정

종료 조건: ADR 4건 승인, 평가셋 동결.

### 1단계: 수집과 기준선(A/B)

- 불변 원본 저장, 해시 기반 중복 제거
- Document IR과 형식별 Adapter (PDF·텍스트 먼저, 이후 HWPX·XLSX)
- 내장 검색 인덱스
- 원본 버전 수집
- CLI: `init`, `ingest`, `search`, `inspect`, `verify`
- 평가 하네스와 기준 에이전트. gotgan은 답을 생성하지 않고, CLI를 쓰는 에이전트가 답한다

종료 조건: A와 B의 측정값 확보.

### 2단계: 최소 큐레이션 루프와 C 비교

- `propose → 결정적 검증 → approve → apply`를 CLI로 구현
- 신뢰 등급, 변경안 해시 고정, 대상 버전 검사
- 큐레이션은 반수동으로 소량만 수행

종료 조건: C가 합격 기준을 넘으면 3단계로 간다. 넘지 못하면 큐레이션을 축소한다.

### 3단계: 자동화와 탐색 UX

- 수요 기반 자동 큐레이션, stale 전파, 함의 검사
- MCP 서버
- 근거 뷰어 웹(React)
- 권한 전파, 내보내기 시 권한 재검사

### 4단계: 팀·기업 및 확장

- 서버 측 권한 강제, 감사, 동기화, 대규모 검색
- Knowledge Canvas, 문서 산출물 생성(Document Factory)
- SI 프로젝트 모듈: 회의록·의사결정 연결부터 시작하고, 외부 시스템 연동은 대상 시스템의 API 확인 후 설계한다.

## 4. 모듈 구성(안)

모듈러 모놀리스로 시작한다. Curation과 Governance는 변경안 하나의 상태 기계이므로 `core-knowledge` 안에 둔다.

```
gotgan/
├─ docs/adr/
├─ core-source/         # SourceDocument, SourceVersion, Document IR
├─ core-knowledge/      # KnowledgeItem, ChangeProposal, Review, Approval
├─ core-access/         # Vault, Membership, 정책 프로파일
├─ adapter-parser/      # PDF, HWPX, XLSX, 텍스트
├─ adapter-index/       # 내장 검색 인덱스
├─ app-cli/
├─ app-server/          # HTTP, MCP (3단계)
├─ web/                 # 근거 뷰어 (3단계)
└─ eval/                # 평가셋, A/B/C 실험 하네스
```

## 5. 미결정 사항

- 민감 정보 파기와 불변 이력의 충돌 해결 방식
- 개인·팀·기업 Vault 간 동기화와 충돌 해결
- 승인 위험 등급과 사람 승인 필수 범위
- 내부 LLM·임베딩 모델과 배포 라이선스
- 외부 지식 표현 규격과의 호환 여부(명세 검증 후 결정)
